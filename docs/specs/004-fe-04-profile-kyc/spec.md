## Problem Statement

KYC через API заработал в PR #66: чек-лист документов по роли, загрузка, удаление, бенефициары, отправка на проверку. Профиль компании при этом — заглушка с текстом «будет реализовано в Фазе 2», и исправить название, адрес или LEI нельзя, хотя `updateMyOrganization` это умеет. Файл неподходящего типа или размера отклоняет только сервер. Бенефициара нельзя отредактировать, только удалить и добавить заново. В статусах `under_review` и `verified` форма просто скрывается, и пользователь не видит, что именно отправил.

### Что уже есть (main `84ef669`)

| Пункт issue | Состояние |
|---|---|
| Форма профиля | **нет**: `ProfileStub` |
| Редактируемый список бенефициаров | частично: добавить и удалить можно, изменить нельзя |
| Подсказка по сумме долей | **нет**. Issue говорит «не блокер», но сервер отклоняет сумму больше 100%; меньше 100% — подсказка |
| Чек-лист документов по роли | есть, совпадает с бэкендом: 4 типа + `source_of_funds` для кредитора |

| Статус и причина отказа | есть |
| Read-only в `under_review` / `verified` | частично: форма скрыта, данные не показаны |

## Goals

- Профиль, бенефициары и документы находятся на одной странице KYC, каждый на своей вкладке, и у каждой вкладки свой адрес (решение от 2026-10-25).
- Компания может изменить реквизиты в статусах `draft` и `rejected` без обращения к админу.
- Файл не того типа или больше 10 МБ отклоняется до начала загрузки.
- В любом статусе пользователь видит, какие данные и документы компания отправила.

## Non-Goals

- Смена роли или страны компании.
- Подпись документов ЭЦП.
- Проверка документов на клиенте по содержимому.

## Users and Context

**Основные пользователи:** представитель заёмщика или кредитора сразу после регистрации и после отказа в верификации.
**Контекст:** без статуса `verified` закрыты заявки, офферы и сделки, поэтому этот экран — узкое место онбординга.
**Ментальная модель:** анкета с чек-листом: «осталось загрузить 2 документа».

## User Stories

### Story 0: Вкладки страницы KYC

**As a** представитель компании
**I want** переключаться между профилем, бенефициарами и документами на одной странице и открывать нужную вкладку по ссылке
**So that** держать, например, документы в отдельной вкладке браузера, пока правлю профиль

**Acceptance criteria:**

- [ ] **AC-0.1** Given страница KYC When пользователь переключает вкладки «Профиль», «Бенефициары», «Документы» Then адрес меняется, страница не перезагружается, статус и причина отказа видны над вкладками
- [ ] **AC-0.2** Given ссылка на вкладку «Документы» When её открывают в новой вкладке браузера Then сразу открыта вкладка «Документы»
- [ ] **AC-0.3** Given изменения сохранены в одной вкладке браузера When пользователь переключается на другую вкладку браузера с той же страницей Then после обновления данных видны сохранённые изменения
- [ ] **AC-0.4** Given открыт старый адрес `/profile` When страница загружается Then пользователя перенаправляет на вкладку «Профиль» страницы `/kyc`
- [ ] **AC-0.6** Given в форме профиля несохранённые изменения When пользователь переключает вкладку Then показано предупреждение с выбором «Остаться» или «Уйти без сохранения»
- [ ] **AC-0.5** Given на любой вкладке When пользователь смотрит блок отправки Then видно, чего не хватает для отправки на проверку на всех трёх вкладках

### Story 1: Редактирование профиля

**As a** представитель компании в статусе `draft` или `rejected`
**I want** исправить название, адрес, рег. номер и LEI
**So that** данные совпали с документами и реестром

**Acceptance criteria:**

- [ ] **AC-1.1** Given статус `draft` When пользователь меняет адрес и сохраняет Then `GET /organizations/me` возвращает новый адрес, а шапка показывает актуальное название
- [ ] **AC-1.2** Given статус `under_review` When пользователь открывает профиль Then все поля только для чтения, кнопки сохранения нет
- [ ] **AC-1.3** Given пользователь очистил поле LEI When сохраняет Then уходит `lei: ""`, и LEI удаляется
- [ ] **AC-1.4** Given сервер вернул ошибку по полю `name` When ответ обработан Then ошибка показана под полем

### Story 2: Бенефициары

**As a** представитель компании
**I want** добавлять, изменять и удалять бенефициаров и видеть сумму долей
**So that** правильно раскрыть структуру владения

**Acceptance criteria:**

- [ ] **AC-2.1** Given два бенефициара по 30% When список показан Then видна подсказка «Сумма долей 60%», и отправка на проверку не блокируется
- [ ] **AC-2.2** Given изменение сделает сумму долей больше 100% When пользователь сохраняет Then под списком ошибка «Сумма долей больше 100%», и запрос не уходит (сервер отклоняет такой список, `checkOwnershipTotal`)
- [ ] **AC-2.3** Given бенефициар в списке When пользователь меняет его долю и сохраняет Then на сервер уходит весь список с изменённой долей, остальные записи не меняются
- [ ] **AC-2.4** Given 50 бенефициаров (максимум контракта) When пользователь пытается добавить ещё одного Then добавление недоступно с пояснением

### Story 3: Загрузка документов

**As a** представитель компании
**I want** перетащить файл в нужный пункт чек-листа и видеть прогресс
**So that** быстро загрузить пакет документов

**Acceptance criteria:**

- [ ] **AC-3.1** Given файл 11 МБ When пользователь бросает его в пункт «Устав» Then показана ошибка «Файл больше 10 МБ», и запрос не уходит
- [ ] **AC-3.2** Given файл `.docx` When пользователь его выбирает Then ошибка «Допустимы PDF, PNG, JPEG», и запрос не уходит
- [ ] **AC-3.3** Given допустимый файл When идёт загрузка Then у пункта виден прогресс, а остальные пункты остаются доступными
- [ ] **AC-3.6** Given в пункте «Устав» уже есть файл When пользователь загружает второй Then в пункте видны оба файла, у каждого кнопки «Скачать» и «Удалить»
- [ ] **AC-3.4** Given документ загружен When пользователь нажимает на имя файла Then файл скачивается через `downloadDocument`
- [ ] **AC-3.5** Given загружены все обязательные документы и есть хотя бы один бенефициар When экран показан Then кнопка «Отправить на проверку» активна; иначе неактивна с перечнем недостающего

### Story 4: Статусы

**As a** представитель компании
**I want** понимать текущий статус и что делать дальше
**So that** не ждать впустую

**Acceptance criteria:**

- [ ] **AC-4.1** Given статус `rejected` с причиной When экран открыт Then причина видна сверху, форма и документы редактируемы
- [ ] **AC-4.2** Given статус `under_review` When экран открыт Then профиль, бенефициары и документы видны только для чтения, документы можно скачать
- [ ] **AC-4.3** Given отправка на проверку прошла When сервер ответил Then статус в шапке и guard'ах сменился на `under_review` без перезагрузки

## Functional Requirements

### FR-0: Одна страница с вкладками

**Must:**
- собрать профиль, бенефициаров и документы на одной странице KYC вкладками; текущая вкладка хранится в адресе;
- показывать статус, причину отказа и кнопку «Отправить на проверку» вне вкладок;
- перенаправлять со старого `/profile` на вкладку «Профиль».

**Must not:**
- терять несохранённый ввод формы при переключении вкладки без предупреждения.

### FR-1: Профиль

**Must:**
- редактировать `name`, `legal_address`, `registration_number`, `lei` через `updateMyOrganization` с ограничениями `OrganizationUpdate`;
- показывать страну и роль без возможности изменить.

### FR-2: Бенефициары

**Must:**
- добавлять, изменять, удалять; сохранять весь список целиком (PATCH заменяет список);
- показывать сумму долей; сумма до 100% включительно — только подсказка;
- блокировать сохранение списка с суммой больше 100%, как это делает сервер.

**Must not:**
- блокировать отправку на проверку из-за суммы меньше 100%.

### FR-3: Документы

**Must:**
- проверять тип (PDF, PNG, JPEG) и размер (до 10 МБ) до отправки; держать эти лимиты в одном месте рядом с хуком загрузки;
- загружать перетаскиванием и выбором файла, с прогрессом;
- скачивать и удалять (удалять только в `draft` / `rejected`);
- показывать все файлы пункта: сервер хранит несколько файлов одного типа и не заменяет старый (сейчас экран показывает только первый). Пункт выполнен, если в нём есть хотя бы один файл.

### FR-4: Режим только для чтения

**Must:**
- в `under_review` и `verified` показывать все данные без элементов редактирования.

### FR-5: Термины в интерфейсе

Решение по фидбеку демо 29.10 (`docs/questions/cp-2.md`, п. 2).

**Must:**
- называть процесс «проверка компании» — и клиенту, и в админке («Проверка компаний», «Подтвердить компанию» / «Отклонить»);
- подписывать статусы только через `kycStatusLabel` (`lib/labels.ts`): Черновик → На проверке → Подтверждена / Отклонена.

**Must not:**
- показывать слово «KYC» и «верификация» в текстах интерфейса и уведомлений; в коде и API имена с `kyc` остаются.

## Non-Functional Requirements

### Performance

- Загрузка одного документа не блокирует работу с остальными пунктами.

### Security

- Скачивание идёт по cookie-сессии; ссылка на файл не сохраняется в хранилище браузера.

### Reliability

- Обрыв загрузки оставляет пункт в состоянии «не загружен» с возможностью повторить.

## Error Scenarios

| Scenario | Expected Behavior |
|----------|-------------------|
| 413 `FILE_TOO_LARGE` (клиентская проверка обойдена) | Сообщение «Файл больше 10 МБ» у пункта |
| 400 при submit: нет документов | Список недостающих документов из `details` |
| 409 `INVALID_STATUS_TRANSITION` при правке (статус изменился в другой вкладке) | Сообщение и перезагрузка данных профиля |
| Сеть оборвалась при загрузке | Ошибка у пункта, кнопка «Повторить» |

## Open Questions

Все вопросы закрыты 2026-10-25 (правила сверены с `backend/internal/service/kyc`):

- Профиль, бенефициары и документы — одна страница `/kyc` с вкладками, вкладка в адресе.
- При переключении вкладки с несохранённым вводом показываем предупреждение (FR-0). Черновики форм не храним.
- Реквизиты и бенефициаров можно менять только в `draft` и `rejected` (`NextKycStatus(..., KycEdit)`). В `under_review` и `verified` всё только для чтения; смена реквизитов верифицированной компании — вне MVP.
- На один тип документа можно загрузить несколько файлов, новый файл не заменяет старый.
- Сумма долей больше 100% блокирует сохранение, потому что так делает сервер.

## Out of Scope (Future Considerations)

- Предпросмотр PDF в браузере.
- История версий документов.
