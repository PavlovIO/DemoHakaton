# Feature 002: FE-02 — layout, навигация по ролям, адаптивность (доработка)

**Status:** Approved
**Created:** 2026-10-25
**Branch:** `002-fe-02-layout-navigation`

## Problem Statement

Шапка и guard'ы есть, но карта маршрутов не совпадает ни с issue, ни с картой экранов из #51. Все шесть пунктов меню админа открывают одну и ту же панель, карточка заявки — заглушка `<div>Детали заявки</div>`. Общих компонентов нет, поэтому каждый экран заново собирает бейджи статусов, пустые состояния и подтверждения через `prompt()` / `confirm()`. Кейс требует адаптивности для ПК и планшета, а на планшете меню сейчас сворачивается в иконки без подписей.

## Goals

- Каждый экран из карты #51 доступен по своему адресу, и адрес можно открыть напрямую или обновить страницу.
- Каждый пункт меню каждой роли открывает свой экран.
- Статусы всех сущностей отображаются одним компонентом с одним словарём подписей и цветов.
- На ширине 768–1024 px все экраны работают без горизонтальной прокрутки страницы.

## Non-Goals

- Наполнять экраны FE-05…FE-14 (они закрыты). Здесь нужны маршрут, layout и общие компоненты.
- Мобильная вёрстка уже 768 px.
- Тёмная тема.

## Users and Context

**Основные пользователи:** заёмщик, кредитор, администратор.
**Контекст:** работа в течение дня на ПК, просмотр с планшета.
**Ментальная модель:** «кабинет» своей роли с постоянным меню и понятным статусом компании.

## User Stories

### Story 1: Навигация по своей роли

**As a** пользователь любой роли
**I want** видеть меню только своих разделов и попадать по каждому пункту на свой экран
**So that** я не путался в чужих функциях

**Acceptance criteria:**

- [ ] **AC-1.1** Given вошёл админ When он по очереди открывает каждый пункт меню Then открываются шесть разных экранов, и активный пункт подсвечен
- [ ] **AC-1.2** Given вошёл заёмщик When он вводит адрес раздела админа Then его перенаправляет в свой кабинет, и запросы к `/admin/*` не уходят
- [ ] **AC-1.3** Given пользователь на экране карточки заявки When он обновляет страницу Then открывается та же карточка
- [ ] **AC-1.4** Given адрес не существует When его открывают Then показывается страница «не найдено» со ссылкой в кабинет

### Story 2: Неверифицированная компания

Решение от 2026-10-25: неверифицированного пользователя уводим на страницу KYC, потому что ему всё равно нужно загрузить документы. Баннера в кабинете нет.

**As a** заёмщик или кредитор с компанией не в статусе `verified`
**I want** сразу попадать туда, где проходят верификацию
**So that** не искать, почему мне недоступны функции

**Acceptance criteria:**

- [ ] **AC-2.1** Given статус компании `draft`, `rejected` или `under_review` When пользователь открывает любой экран кабинета, кроме KYC Then его перенаправляет на страницу KYC, и запросы того экрана не уходят
- [ ] **AC-2.2** Given статус не `verified` When пользователь смотрит меню Then разделы, требующие верификации, недоступны, а пункт KYC доступен
- [ ] **AC-2.3** Given статус сменился на `verified` (админ одобрил) When пользователь обновляет данные сессии или страницу Then разделы кабинета открываются без повторного входа
- [ ] **AC-2.4** Given компании у пользователя нет (`organization: null`) When он открывает кабинет Then его уводит на заполнение профиля

### Story 3: Планшет

**As a** пользователь на планшете
**I want** пользоваться всеми разделами без горизонтальной прокрутки
**So that** работать не только за ПК

**Acceptance criteria:**

- [ ] **AC-3.1** Given ширина окна 768 px When открыт любой экран из карты #51 Then у страницы нет горизонтальной прокрутки; широкие таблицы прокручиваются внутри своего блока
- [ ] **AC-3.2** Given ширина 768 px When открыт кабинет любой роли Then каждый пункт меню доступен с подписью: прямо в шапке или в меню «Ещё»

### Story 4: Единые компоненты

**As a** пользователь
**I want** чтобы статусы, подтверждения и пустые списки выглядели одинаково на всех экранах
**So that** интерфейс был предсказуемым

**Acceptance criteria:**

- [ ] **AC-4.1** Given статус оффера `sent` When он показан на любом экране Then подпись и цвет одинаковые
- [ ] **AC-4.2** Given необратимое действие (отозвать оффер, отклонить заявку) When пользователь его запускает Then открывается модальное окно подтверждения, а не системный диалог браузера
- [ ] **AC-4.3** Given список пуст When экран загружен Then показан блок пустого состояния с текстом для этого списка
- [ ] **AC-4.4** Given список загружается When данных ещё нет Then показан индикатор загрузки, а не «Список пуст»

## Functional Requirements

### FR-1: Карта маршрутов

**Must:**
- покрыть все экраны из таблиц `frontend/docs/ux/user-flows.md` для трёх ролей, кроме `/offers/:id/messages` (чат — модалка);
- плоские маршруты без префикса роли; KYC на `/kyc`, редирект со старых `/profile` и `/profile/kyc`;
- дать каждому пункту меню админа отдельный маршрут и экран, пусть даже с минимальным содержимым;
- иметь страницу 404.

**Must not:**
- оставлять маршруты-заглушки вида `<div>Детали заявки</div>`.

### FR-2: Guard'ы

**Must:**
- без сессии уводить на `/login` с возвратом на исходный адрес;
- уводить с маршрута чужой роли в свой кабинет;
- уводить неверифицированных заёмщиков и кредиторов на страницу KYC (Story 2); админа это правило не касается.

### FR-3: Layout

**Must:**
- шапка: название компании, роль, колокольчик уведомлений, выход;
- горизонтальное меню по роли в шапке (бокового нет);
- бейдж статуса KYC компании в шапке.

### FR-4: Общие компоненты

**Must:**
- таблица со страничной догрузкой;
- панель фильтров, синхронизированная с query-строкой адреса;
- бейдж статуса со словарём для заявок, офферов, сделок, KYC и AML-флагов;
- модалка подтверждения, в том числе с обязательным полем причины (её переиспользует FE-12);
- пустое состояние, индикатор загрузки, состояние ошибки.

## Non-Functional Requirements

### Performance

- Переход между разделами без перезагрузки страницы. Сейчас логотип в шапке — `<a href>`, и клик перезагружает всё приложение.

### Security

- Скрытый пункт меню не заменяет guard: маршрут закрыт и при прямом вводе адреса.

### Reliability

- Ошибка рендера одного экрана не роняет layout: меню и шапка остаются.

## Error Scenarios

| Scenario | Expected Behavior |
|----------|-------------------|
| `getMe` вернул 5xx при старте | Экран ошибки с кнопкой «Повторить», а не редирект на логин |
| Сессия истекла на открытом экране | Редирект на `/login` с возвратом на исходный адрес |
| Компании пользователя нет (`organization: null`) | Редирект на заполнение профиля |

## Open Questions

Все вопросы закрыты 2026-10-25:

- Маршруты плоские, как в карте #51 и в коде (`/applications`, `/offers`, `/deals`). Префиксов ролей `/borrower/*` и `/lender/*` нет; у админа остаётся `/admin/*`. Пункт issue изменён.
- Меню горизонтальное, в шапке. На ширине от 768 px пункты показываются с подписями; если не помещаются — переносятся или уходят в меню «Ещё».
- Страница KYC — `/kyc`. Старые `/profile` и `/profile/kyc` перенаправляют на неё.
- Неверифицированных пользователей уводим на `/kyc`, баннера нет.
- Чат остаётся модалкой на экране оффера, отдельного маршрута `/offers/:id/messages` нет.

## Out of Scope (Future Considerations)

- Мобильная вёрстка.
- Настройка меню пользователем.
