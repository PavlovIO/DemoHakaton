# Feature 006: FE-15 — безопасность и качество фронтенда (доработка)

**Status:** Approved
**Created:** 2026-10-25
**Branch:** `006-fe-15-frontend-security-quality`
**Issue:** #47

## Problem Statement

Фактически опасных мест в коде сейчас нет: HTML из пользовательского текста не рендерится, данные в `localStorage` не лежат (их убрали при переходе на API). Но гарантировано это только ревью: правила линтера нет, и следующий PR может вернуть и то и другое. Совместимость с CSP никто не проверял, а библиотека тостов вставляет стили в рантайме. Тестов компонентов нет вообще: есть только интеграционные тесты хуков и страниц против живого бэкенда, и валидацию форм заявки и оффера ничто не проверяет.

### Что уже есть (main `84ef669`)

| Пункт issue | Состояние |
|---|---|
| Запрет `dangerouslySetInnerHTML` линтером | **нет** правила; использований в `src/` тоже нет |
| Без inline-скриптов и стилей в production | **не проверено**; `index.html` чистый, но `sonner` внедряет `<style>` в рантайме |
| Нет токенов и данных в `localStorage` | выполнено по факту, не закреплено |
| Тест клиента API (CSRF) | есть, интеграционный (`api-client.integration.test.ts`) |
| Тесты формы заявки и формы оффера | **нет** |

## Goals

- Линтер в pre-commit и CI отклоняет `dangerouslySetInnerHTML`, `innerHTML` и обращения к `localStorage` / `sessionStorage`.
- Production-сборка открывается без нарушений CSP под целевой политикой из Open Questions.
- Валидация форм заявки и оффера покрыта быстрыми тестами, которые не требуют поднятого бэкенда.

## Non-Goals

- Пентест и аудит зависимостей сверх `npm audit` (это BE-15 / инфраструктура).
- Подбор CSP для API: бэкенд уже отдаёт `default-src 'none'; frame-ancestors 'none'`.
- E2E-тесты в браузере.

## Users and Context

**Основные пользователи:** разработчики фронтенда, ревьюеры.
**Затронуты:** все пользователи (защита от XSS и кражи сессии).
**Контекст:** каждый PR во фронтенд.

## User Stories

### Story 1: Запрет опасного рендера

**As a** ревьюер
**I want** чтобы линтер отклонял рендер пользовательского текста как HTML
**So that** XSS не вернулся незамеченным

**Acceptance criteria:**

- [ ] **AC-1.1** Given компонент с `dangerouslySetInnerHTML` When запускается линтер Then он падает с ошибкой, указывающей на строку
- [ ] **AC-1.2** Given код с присваиванием `element.innerHTML` When запускается линтер Then он падает
- [ ] **AC-1.3** Given сообщение чата `<img src=x onerror=alert(1)>` When оно отображается Then на экране этот текст, и скрипт не выполняется

### Story 2: Без хранения в браузере

**As a** специалист по безопасности
**I want** чтобы токены и персональные данные не попадали в хранилище браузера
**So that** XSS не мог их унести

**Acceptance criteria:**

- [ ] **AC-2.1** Given код с `localStorage.setItem` или `sessionStorage` When запускается линтер Then он падает
- [ ] **AC-2.2** Given пользователь прошёл вход, KYC и создал заявку When проверяется хранилище браузера Then в `localStorage` и `sessionStorage` нет записей приложения

### Story 3: Совместимость с CSP

**As a** DevOps
**I want** чтобы production-сборка работала под строгой CSP
**So that** включить политику без поломок

**Acceptance criteria:**

- [ ] **AC-3.1** Given production-сборка When проверяются `index.html` и бандл Then в них нет inline `<script>` и атрибутов-обработчиков `on*`
- [ ] **AC-3.2** Given сборка открыта под целевой CSP (Open Questions) When пользователь проходит вход, показ тоста, открытие модалки Then в консоли нет нарушений CSP
- [ ] **AC-3.3** Given проверка CSP When она падает Then CI-джоба фронтенда красная

### Story 4: Тесты ключевых форм

**As a** разработчик
**I want** быстрые тесты валидации форм
**So that** не поднимать бэкенд ради проверки правила суммы

**Acceptance criteria:**

- [ ] **AC-4.1** Given форма оффера по заявке на `1000000.00` When введена сумма `1000000.01` Then форма показывает ошибку и не вызывает отправку
- [ ] **AC-4.2** Given форма оффера When введены `0`, отрицательная сумма или три знака после запятой Then ошибка под полем суммы
- [ ] **AC-4.3** Given форма заявки When не заполнены обязательные поля или срок вне допустимого диапазона Then ошибки под полями, отправка не вызвана
- [ ] **AC-4.4** Given клиент API When выполняется POST при cookie `csrf_token=abc` Then запрос содержит `X-CSRF-Token: abc`; при GET заголовка нет (тест без бэкенда)
- [ ] **AC-4.5** Given CI When в PR меняется фронтенд Then эти тесты запускаются и блокируют merge при падении

## Functional Requirements

### FR-1: Правила линтера

**Must:**
- запрещать `dangerouslySetInnerHTML`, присваивание `innerHTML` / `outerHTML`, `document.write`;
- запрещать `localStorage` и `sessionStorage` в коде приложения (тесты-исключения — по комментарию с обоснованием).

### FR-2: CSP

**Must:**
- собирать production без inline-скриптов;
- работать под целевой политикой; единственное исключение — `style-src 'unsafe-inline'` для стилей, которые внедряются в рантайме.

### FR-3: Модульные тесты

**Must:**
- отдельная конфигурация тестов, не требующая бэкенда, рядом с интеграционной;
- правила валидации форм заявки и оффера — в отдельных модулях, тесты Story 4 — на эти модули;
- запуск только в CI, блокирует merge.

## Non-Functional Requirements

### Performance

- Модульные тесты проходят быстрее 30 секунд на машине разработчика.

### Security

- Ни одно правило не отключено глобально; исключения — только точечные, с причиной.

### Reliability

- Модульные тесты детерминированы: без сети и без реального времени.

## Error Scenarios

| Scenario | Expected Behavior |
|----------|-------------------|
| Зависимость внедряет inline-стиль | Проверка CSP падает с указанием источника |
| Разработчику нужен HTML (например, справка) | Только через санитайзер и с точечным исключением в линтере, согласованным на ревью |

## Open Questions

Все вопросы закрыты 2026-10-25:

- Кто отдаёт фронтенд в production, решит отдельная инфраструктурная задача (по аналогии с INF-01 для бэкенда). Здесь фиксируем целевую политику, под которую проверяется сборка:
  `default-src 'self'; script-src 'self'; style-src 'self' 'unsafe-inline'; img-src 'self' data:; connect-src 'self'; frame-ancestors 'none'; base-uri 'none'; form-action 'self'`.
- `style-src 'unsafe-inline'` пока допускаем: `sonner` вставляет `<style>` в рантайме. Inline-скрипты запрещены без исключений. Убрать `'unsafe-inline'` из стилей — в Out of Scope.
- Правила валидации форм заявки и оффера выносим в отдельные модули и тестируем без рендера. Рендер-тест формы нужен один: ошибка показана у поля.
- Модульные тесты гоняем только в CI; в pre-commit остаются eslint и tsc.

## Out of Scope (Future Considerations)

- Subresource Integrity для внешних ресурсов (их сейчас нет).
- Отдача фронтенда в production и выставление CSP-заголовка — отдельная инфраструктурная задача.
- Убрать `style-src 'unsafe-inline'`: заменить библиотеку тостов или подключать её стили файлом.
- Trusted Types.
