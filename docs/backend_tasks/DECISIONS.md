# Решения по планам бэкенда

Итоги опроса по открытым вопросам планов (23.10.2026). Если решение здесь расходится с «Открытыми вопросами» или «Решениями» в плане задачи, главнее этот файл. В скобках — планы, которые надо привести в соответствие.

## Аутентификация, доступ, контракт

1. **CSRF для `register` и `login` не проверяется.** Исключение — операции с `security: []`; записать в `api/openapi.root.yaml` (`info.description`), `backend/README.md` и `AGENTS.md`. Защита от login-CSRF — обязательный `Content-Type: application/json`. (BE-03, BE-04)
2. **`'403': Forbidden` добавляется ко всем операциям без `security: []`** одним коммитом в шаге «Контракт» BE-04, плюс тест «у каждой защищённой операции есть 403» рядом с тестом на `x-roles`. (BE-03, BE-04, BE-08, BE-09, BE-10)
3. **BE-04 проверяет видимость интеграционным тестом запросов**; HTTP-тесты IDOR по всем ресурсам — в BE-15. (BE-04, BE-15)
4. **IP клиента — из `RemoteAddr`.** `X-Forwarded-For` с `TRUSTED_PROXIES` — когда появится прод. (BE-03, BE-14, BE-15)
5. **CORS в dev не нужен:** фронт ходит через proxy Vite (`/api` → `localhost:8080`, `frontend/vite.config.ts` в ветках `frontend-setup` и `feat/frontend-applications-kyc`). (BE-15)

## Коды ошибок и PATCH

6. **Правило 409:** недопустимый переход статуса → `INVALID_STATUS_TRANSITION`; данные мешают действию → `CONFLICT`. Отсюда: «заявка не принимает офферы» → `CONFLICT`; approve KYC при открытых `high`-флагах → `CONFLICT`; просроченный оффер (`valid_until` в прошлом) при принятии → `INVALID_STATUS_TRANSITION`, статус оффера не меняется. (BE-08, BE-09, BE-12)
7. **Очистка nullable-поля в PATCH — пустой строкой `""` → `NULL`** (в SQL `NULLIF(…, '')`). Правило одно для всех PATCH (`lei`, `transfer_method_comment` и др.), описывается в контракте у каждого такого поля. (BE-05, BE-07)

## Бизнес-правила

8. `submitKyc` требует хотя бы одного бенефициара → иначе 400 `VALIDATION_ERROR`, поле `beneficiaries`; дописать в `description` операции. (BE-05)
9. `offers_count` — все офферы заявки в любом статусе; записать в описание поля. (BE-07)
10. Кредитор видит историю заявки без комментариев модерации (`comment` у записей `entity_type = application` обнуляется в сервисе). (BE-07)
11. Кредитор видит только свой оффер по заявке. (BE-08)
12. `actor` автоматически отклонённых офферов — заёмщик; причина — в `comment`. (BE-07, BE-09)
13. Публикация заявки при открытых `high`-флагах не блокируется; решение за админом. (BE-12)

## Уведомления, чат, аудит

14. Уведомления: `deal_created` заёмщику не шлём; админу — ни о новом оффере, ни об отмене заявки в `moderation`; `aml_flag_created` — одно на прогон скрининга, не на флаг; в чате — одно уведомление на сообщение. (BE-07, BE-08, BE-09, BE-10, BE-11, BE-13)
15. Чат: лимит 20 сообщений в минуту на пользователя; сообщение из одних пробелов принимается; первая загрузка — 50 самых старых. (BE-10)
16. Аудит: `document.download` админом пишется; `auth.logout` — нет; email при `auth.login_failed` с `unknown_email` не хранится. (BE-05, BE-14)

## Реестры и AML

Адаптеров DaData/GLEIF, `REGISTRY_PROVIDER`, `DADATA_API_KEY`, `REGISTRY_TIMEOUT` нет. Ветку `docs/adr-0001-kyc-aml-mocks` смержить как есть («в MVP — моки, сетевых вызовов и API-ключей нет»). ## Сверка планов (23.10.2026)

36. **Роль и KYC проверяют и middleware (`x-roles`, `x-kyc-required`), и сервис** — защита в глубину. Middleware даёт ранний отказ до валидатора; проверка в сервисе — одна строка, тестируется юнит-тестом без роутера и страхует от ошибки в спеке. Правило `AGENTS.md` «роль проверяй в сервисе» остаётся. (BE-04, BE-05, BE-07, BE-08, BE-09, BE-10)
37. **Фильтр витрины по способу перевода** — параметр-массив `transfer_method` в `listApplications` (ИЛИ, как `target_country`), в SQL `sqlc.narg('transfer_methods')::text[]`. (BE-07)

## Раунд 4 — остаток открытых вопросов (23.10.2026)

38. **Кэш ответов реестра не делаем.** Реестр — мок (п. 17); лимиты BE-06 (10/мин с IP, 60/мин всего). Фронт вызывает lookup по blur или кнопке, а не на каждый символ — пометка для FE-04. (BE-06)
39. **Старые уведомления в MVP не чистим**; записать в «Что сознательно не делаем» в `docs/db/schema.md`. (BE-11)
40. **`%`, `_` и `\` в поиске `q` экранируются**: в Go — `escapeLike(q)`, в SQL — `ILIKE '%' || @q || '%' ESCAPE '\'`. (BE-12)
41. **Транслитерация для AML — две схемы сразу: ICAO и BGN/PCGN, берётся максимум score.** Иначе `Юрий` (`iurii`) не находит `Yuri` в UK-списке. (BE-13)
42. **`user_id`/`org_id` в логах** — атрибуты контекста `middleware.WithLogAttrs`, их дополняет `Authenticate` после проверки сессии; `ContextHandler` от `service` не зависит. (BE-14)
43. **CSP для SPA ставит INF-01**: frontend-контейнер (nginx) отдаёт prod-сборку с заголовком CSP из плана BE-15; dev-сервер Vite — без CSP. Строку вписать в issue INF-01. (BE-15)
44. **`MaxHeaderBytes` — дефолт Go (1 МБ)**: заголовки ограничены по времени `ReadHeaderTimeout`. (BE-15)
45. **Сид вставляет AML-флаги SQL-ом, скрининг не запускает**: детерминированно, без зависимости сида от BE-13; формат `details` сторожит `TestSeedFlagDetails`. (BE-16)
