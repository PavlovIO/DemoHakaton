# ADR-0003: Сгенерированный сервер — пакет на тег

**Status:** Proposed
**Date:** 2026-10-22
**Deciders:** бэкенд
**Supersedes:** ADR-0001, Action Items п. 3 — фраза «разнести по тегам oapi-codegen не умеет»; ADR-0002, п. 2 — «два конфига пишут в один пакет»

## Context

`internal/http/api/server.gen.go` содержал все 51 операцию — 6787 строк, разложенных по слоям генератора (обёртки параметров, роутинг, Request/Response-объекты, strict-адаптеры), а не по доменам. Один `StrictServerInterface` на 51 метод. Критерий хакатона «код структурирован» оценивают по репозиторию, и такой файл читается как свалка, хотя он сгенерирован. Кроме того, любое изменение спеки в параллельных PR даёт конфликт в одном и том же огромном файле.

Несколько файлов в одном пакете не решают проблему: каждый запуск с `include-tags` объявляет одни и те же `ServerInterface`, `StrictServerInterface`, `HandlerWithOptions` и т.д. Модели по доменам тоже не разнести: схемы ссылаются друг на друга по кругу (`organizations` ↔ `auth`, `organizations` ↔ `aml`), а Go запрещает циклы импортов.

Реализовано 4 операции из 51 — переход сейчас почти бесплатный.

## Decision

```
internal/http/api/
  models.gen.go          # все схемы — один пакет api (как раньше)
  doc.go                 # описание раскладки
  <tag>api/              # 10 пакетов: auth, organizations, dictionaries, applications,
    gen.go               #   offers, deals, chat, notifications, admin, system
    register.go          # Register(mux, si, baseURL, reqErr, respErr) — руками, одинаковый во всех
    server.gen.go        # операции одного тега (279–2225 строк)
internal/http/handler/
  <tag>.go               # реализации и заглушки операций тега
```

- **Один `oapi-codegen/server.yaml` на все теги.** Пакет, тег и выходной файл задают флаги `-package`, `-include-tags`, `-o` в `//go:generate` пакета (флаги переопределяют конфиг). `make gen-api` = models + `go generate ./internal/http/api/...` — новый тег не требует правок Makefile.
- **Модели — dot-import** (`additional-imports: [{alias: "."}]`): сгенерированный код ссылается на `Error`, `OfferID` без префикса. Поэтому в пакет `api` нельзя добавлять рукописные типы — они попадут в каждый `<tag>api` и могут столкнуться со сгенерированными именами (`doc.go`).
- **Один `*Handler` реализует все 10 интерфейсов** (operationId уникальны по спеке) — 10 compile-time проверок в `handler.go`. Отдельный тип на домен с узкими `Deps` возможен позже, без изменения раскладки.
- **Роутинг:** `routes()` в `router.go` вызывает `<tag>api.Register` на общем `ServeMux`; middleware-цепочка и валидатор не изменились.
- **Ошибки параметров.** Типы `InvalidParamFormatError`, `RequiredParamError` и др. генерируются в каждый пакет заново, `errors.As` по конкретному типу потребовал бы 6 × 10 веток. `paramName` (`handler/errors.go`) читает поле `ParamName string` через reflect, но только у типов из `internal/http/api/<tag>api`; покрыто прямым табличным тестом.

### Инварианты (тесты в `handler/routes_test.go`)

- У каждой операции спеки ровно один тег, и для него есть пакет. Без тега или с новым тегом операция молча выпала бы из роутинга, с двумя — `ServeMux` упал бы с паникой на дубле.
- Каждая операция спеки зарегистрирована на mux (`ServeMux.Handler` не возвращает fallback `/`). Проверяется сам mux, а не HTTP-ответ: через полный роутер многие запросы отбил бы валидатор раньше роутинга. Тест проверен мутацией: без `chatapi.Register` падает на `listMessages`/`sendMessage`.

## Consequences

**Положительные**
- Домены видны в дереве: `api/offersapi` (7 операций), `handler/offers.go`. Крупнейший сгенерированный файл — `adminapi` (13 операций, 2225 строк) вместо 6787.
- Изменение спеки в одном теге меняет только его `server.gen.go` — меньше конфликтов между параллельными PR.
- Узкие интерфейсы `<tag>api.StrictServerInterface` (1–13 методов) — их можно реализовать фейком в тесте.
- `*.gen.go` и sqlc помечены `linguist-generated` — GitHub сворачивает их в диффах PR.
- `models.gen.go`, бандл и контракт не изменились; фронт не затронут.

**Отрицательные / принятые**
- В сигнатурах хендлеров — пакет тега: `offersapi.AcceptOfferRequestObject`, модели — `api.Offer`. Ветки с хендлерами, начатые до этого ADR, правятся механически (`api.Xxx{Request,Response}Object` → `<tag>api.…`), компилятор показывает каждое место.
- 10 одинаковых `register.go` (отличается только `package`). Сгенерировать их через user-templates oapi-codegen можно, но сложнее, чем 15 строк руками.
- `components.responses` (`BadRequestJSONResponse`…) дублируются в каждом пакете, который их использует, — это разные типы.
- Новый тег = новый пакет (копия `gen.go`/`register.go`) + строка в `routes()` + строка в `generatedTags`; забытое ловят тесты.
- reflect в `paramName` — на пути только ошибочного запроса, не горячий.

## Отклонённые альтернативы

- **Оставить один `server.gen.go`** и объяснить в README. Дёшево, но не решает ни восприятие структуры, ни конфликты в PR.
- **10 конфигов `server-<tag>.yaml`.** Дублирование общего блока ×10 и правка `gencfg_test.go`; флаги CLI делают то же одним конфигом.
- **Модели по пакетам доменов.** Невозможно из-за циклов в графе схем (см. ADR-0002, «Кормить oapi-codegen сплитом напрямую»).
- **Явный `errors.As` по типам всех пакетов** в `paramError` — 60 веток, каждая новая — при новом теге.
