# Вопросы к чекпоинту 2 — фронтенд

Формат: **как сейчас** → **вопрос** → **что предлагаем** (сделаем так, если нет возражений).

## 1. Английская версия интерфейса

**Как сейчас.** Интерфейс только на русском, локализация вынесена за рамки MVP. Все кредиторы в демо — нерезиденты (Кипр, Германия, Кувейт, Сингапур).

**Вопросы.**
- Нужна ли английская версия к финалу?
- Если да — весь интерфейс или только кабинет кредитора и страницы входа/регистрации?
- Переключатель языка пользователь выбирает сам или язык зависит от страны компании?

**Предлагаем.** Переключатель RU/EN в шапке. Начать с входа, регистрации, KYC и кабинета кредитора; админку оставить на русском.

## 2. Тексты кнопок и статусов KYC

**Решено 29.10** (ветка `fix/kyc-wording`, FR-5 в `docs/specs/004-fe-04-profile-kyc/spec.md`): «проверка компании» везде, включая админку; статусы и кнопки — как в «Предлагаем»; отказ — в модальном окне с обязательной причиной. Вопрос о формулировках заказчика остаётся открытым.

**Как сейчас.**
- Один статус называется по-разному в разных местах: «Не начато» / «Черновик», «Подтверждено» / «Верифицирована».
- Пользователь видит пункт меню «Пройти верификацию (KYC)», у администратора кнопка «Одобрить KYC».
- Причину отказа администратор вводит в системном окне браузера.

**Вопросы.**
- Понятен ли клиенту термин «KYC», или писать «проверка компании»?
- Согласовать ли единые названия статусов?
- Есть ли у заказчика свои формулировки, которые обязательно использовать (юридические, из регламента)?

**Предлагаем.**
- Статусы везде: «Черновик» → «На проверке» → «Подтверждена» / «Отклонена».
- Пользователю — кнопка «Пройти проверку компании», у администратора — «Подтвердить компанию» / «Отклонить».
- Причина отказа — в нормальном окне с обязательным полем.

## 3. Заблокированные пользователи и поддержка

**Как сейчас.**
- Администратор может заблокировать пользователя, причина блокировки обязательна. Организацию целиком заблокировать нельзя.
- Пользователь причину блокировки не видит.
- Контактов поддержки в интерфейсе нет.

**Вопросы.**
- Какой канал поддержки показывать: телефон, email, форма обращения? Чьи это контакты (заказчика или условные)?
- Показывать ли заблокированному пользователю причину блокировки?
- Где показывать контакты: только на экране «Аккаунт заблокирован» или ещё в подвале сайта и на экране отказа KYC?
- Нужна ли блокировка всей организации, а не отдельного пользователя?

**Предлагаем.** При входе заблокированного пользователя — понятное сообщение «Аккаунт заблокирован» и контакт поддержки. Тот же контакт — в подвале сайта.

## 4. Структура админ-панели

**Как сейчас.**
- Сверху есть меню: Аналитика, Очередь KYC, Модерация заявок, AML-флаги, Пользователи, Аудит.
- Под ним вкладки «Очередь KYC / Модерация заявок» ведут на те же страницы, и это выглядит как дубль.

**Вопросы.**
- Какая «главная» нужна администратору: сводка (аналитика и очереди) или сразу очередь KYC?
- Достаточно ли одного меню без подвкладок?
- Нужен ли в MVP экран журнала аудита? Бэкенд его отдаёт, экрана пока нет.

**Предлагаем.**
- Оставить одно верхнее меню и убрать подвкладки.
- Счётчики очередей показывать бейджами в меню.
- Главная администратора — аналитика.
- Экран аудита — простая таблица с фильтрами.

## 5. Проверка документов KYC

**Как сейчас.**
- Компания загружает документы (PDF/PNG/JPEG до 10 МБ), бэкенд их хранит и умеет отдавать.
- В очереди KYC администратор видит только название, страну и рег. номер. Открыть документы из интерфейса пока нельзя.
- Пример: Gamma GmbH (DE). У неё 5 документов и открытый AML-флаг высокой серьёзности (совпадение с санкционным списком), поэтому система не даёт подтвердить её KYC. Это задумано: сначала разобрать флаг, потом решение по компании. Но понятного сообщения об этом сейчас нет.

**Вопросы.**
- Администратору достаточно скачать документ, или нужен просмотр прямо в браузере?
- Верен ли порядок: high-флаг AML → сначала разобрать флаг → потом подтвердить или отклонить KYC?
- Можно ли подтвердить компанию с флагом средней или низкой серьёзности?
- Список обязательных документов. Заёмщику: устав, свидетельство о регистрации, подтверждение адреса, реестр бенефициаров. Кредитору дополнительно — источник средств. Полный ли он?

**Предлагаем.**
- Карточка компании в админке: реквизиты, бенефициары, документы (открыть/скачать), AML-флаги, сверка с реестром.
- Кнопка «Подтвердить» неактивна с подсказкой, пока есть открытый high-флаг.

## 6. Дашборды

**Как сейчас.**
- После входа заёмщик и кредитор попадают на «Дашборд», но там пока только приветствие.
- У администратора есть аналитика:
  - карточки: заявки, на модерации, офферы, сделки;
  - заявки по статусам;
  - суммы и средний чек по каждой валюте отдельно, без пересчёта в одну;
  - топ-5 стран спроса и предложения.
- Аналитика считается за всё время. Бэкенд умеет фильтровать по периоду, в интерфейсе этого фильтра нет.

**Вопросы.**
- Что заёмщик должен видеть на главной: статус проверки компании, свои заявки по статусам, новые офферы, сделки, уведомления?
- Что кредитор должен видеть на главной: новые заявки на витрине, свои офферы и ответы на них, сделки?
- Какие метрики для администратора главные?
- Нужен ли администратору выбор периода (неделя / месяц / квартал / свой)?
- Нужна ли динамика по времени (график по неделям) или достаточно итоговых цифр?
- Пересчитывать ли суммы в одну валюту? Если да — по какому курсу и на какую дату?
- Нужна ли воронка «заявки → офферы → сделки» с конверсией?
- Нужна ли выгрузка в CSV / Excel?

**Предлагаем.**
- Главная пользователя — блок «что требует внимания»: статус проверки компании, новые офферы или ответы, сделки, быстрые ссылки.
- Админу — добавить выбор периода.
- Валюты в MVP не пересчитываем.

## 7. Развёртывание демо

**Как сейчас.** Защита от CSRF работает, только если интерфейс и API открываются с одного сайта. Сейчас так и сделано: фронт и API идут через общий nginx. Cookie сессии помечены Secure, поэтому нужен HTTPS.

**Вопросы.**
- Где будет стоять демо для приёмки: наш сервер, сервер заказчика, туннель?
- Будет ли один домен с HTTPS?
- Есть ли требования к инфраструктуре (Docker, конкретный хостинг, облако РФ)?

**Предлагаем.** Один домен с HTTPS, запуск одной командой через docker compose.

## Известные проблемы — исправляем сами

- Заблокированный пользователь при входе видит «У вас нет прав» вместо «Аккаунт заблокирован».
- При подтверждении KYC компании с high-флагом показывается «данные уже изменились» вместо реальной причины.
- В профиле отображается служебный код роли (`borrower` / `lender`) и текст «Что будет реализовано в Фазе 2».
- Пункт меню «Аудит» ведёт на очередь KYC.
- Счётчики очередей в админке могут показывать 0, пока не открыть саму очередь.
- Ошибки валидации показывают технические имена полей.
- Администратора после входа отправляет на пользовательский «Дашборд», а не в админку.
